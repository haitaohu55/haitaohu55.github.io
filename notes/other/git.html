    Git 是什么

    Git 是一种运行在个人电脑上的记录文件变化的工具，由 Linux 之父 Linus Torvalds 开发。也有人叫他分布式版本控制系统，这里的分布式指的是每个开发者本地都有一个完整的代码仓库。

    Git 存储的是文件随时间变化的快照。这里的文件一般指代码，但事实上他不只限于代码，他还可以是图像、文本文件、甚至是视频，Git 会跟踪文件的每一步变化，这使得分支管理和版本回退极其迅速。

    GitHub/GitLab 是什么

    GitHub/GitLab 是放 Git 仓库的云端。

    Git 架构

    Git 主要分为本地和远程两个部分，本地指个人电脑，远程指云端，例如 GitHub。

    在你的计算机上，你正在处理项目的文件夹称为工作目录。这就是所有改动发生的地方。当你希望保存这个版本时，你把你改动后的文件夹移到 stage。你可以将 stage 视为中间地带。当你确认没问题后，你将 staged 的文件提交到 local repository。在本地仓库里，Git自动创建了一些系统文件，这些文件可以跟踪你的更改、提交等，这些文件完全由 Git 本身管理。

    迄今为止，一切都只发生在你的电个人脑上，还没有任何东西被发送到云端。只有当你想与他人共享代码，或者从另一台计算机访问代码或安全地备份时，你才需要云端。

    Git 快速入门

    初始化本地储存库

    首先打开终端，在终端中输入

    git --version

    确保你已经安装了 git。接下来在桌面上新建一个本地文件夹

    cd ~/Desktop; mkdir git-one

    随后在文件夹中新建两个文本文件

    cd git-one; touch one.txt; touch two.txt

    并新建文件夹

    mkdir myfolder

    进入文件夹 myfolder 新建一个文本文件

    cd myfolder; touch three.txt

    随后你可以打开当前文件件，确认所有文件都被正确生成了

    open .

    接着在 one.txt 里写 one，two.txt 里写 two，three.txt 里写 three。接下去，我希望用 git 来监控这个文件夹，就进入 git-one 这个文件夹初始化 git

    git init

    你可以通过

    ls -a

    确认这一点。

    Github 上创建远程储存库

    进入

    https://github.com

    点击左边的 new，输入仓库名和描述，再点击 create，就可以新建一个空仓库。接着我们点击 creating a new file，新建一个文件名 one.txt，并输入内容 one，然后commit 就行。同样的方式处理 two.txt。随后你就能在仓库里看到两个新建的文本文件。

    克隆 Github 上的远程储存库

    我们在终端输入

    cd ../; git clone https://github.com/haitaohu55/git-learing

    这里的链接是你的储存库的 URL。这样，你就能在桌面上找到克隆下来的文件夹。进入文件夹后，你同样可以找到 .git 文件夹

    cd git-learing; ls -a

    查看文件夹中所做的修改

    试着对 git-learing 文件夹中的 one.txt 文件做点修改并保存，随后输入

    git status

    你会看到显示 one.txt 被 modified。通过 git status，你可以轻松检查工作目录中文件的更改。

    将更改移动到暂存区

    如下命令可以把工作区的所有改动推到暂存区

    git add --all

    随后你可以确认这一点

    git status

    通过

    git reset

    你可以撤销这次提交

    类似的操作有

    git add -A
git add .
git add one.txt
git add myfolder/three.txt

    从暂存提交到本地存储库

    当你确认暂存区的东西没问题了，你就可以把暂存区的内容提交到本地存储库

    git commit

    之后终端会跳出来让你输入说明，输入完后按 esc 退出编辑模式后，依次打

    :wq

    即可保存退出。当然你也可以一步到位

    git commit -m "make some changes"

    这里 -m 就是 message 的缩写。接着通过

    git status

    你可以检查是否提交完成。如果你要撤销这次 commit，你可以通过

    git reset HEAD~1

    来实现，这样所有修改就回到工作区了，暂存区和本地存储库都撤销了这次修改。

    删除和恢复文件

    你可以直接从文件夹中删去 one.txt，随后输入

    git status

    你可以看到 one.txt 确实被删掉了，随后

    git add --all

    可以把这次删除提交到暂存区。事实上，你可以通过

    git rm one.txt

    实现如上两个步骤。如果你只是要撤销上传到暂存区

    git reset

    就够了，如果你要撤销上传并恢复文件，你需要

    git reset --hard

    需要注意的是 rm 不允许删除更改后没提交的文件，如果要强制删除要用

    git rm -f one.txt

    要删除文件夹则要用

    git rm -r myfolder

    查看历史提交记录

    通过

    git log

    你可以查看历史提交记录。并附带提交记录的ID。如果你希望简洁一点，你可以试试

    git log --oneline

    新建分支

    分支是 Git 最强大的功能，想象一下你推出了一个软件，提交了一次记录 C1，现在一部分人负责改 bug，一部分人负责出新功能。这时候你就可以新建一个分支

    git branch bugFix

    对于改 bug 的人而言，他们就切到分支 bugFix 上进一步提交

    git checkout bugFix
git commit

    对于开发新功能的人就接着在 main 分支提交。你可以通过

    git status

    查看在哪个分支。

    合并分支

    最终，你一定需要合并分支。假定你是负责改 bug 的，你一直在 bugFix 分支工作，当处理新版功能后，你不希望在老版文件上改 bug，你就可以

    git merge main

    随后改完 bug 后，你可以切到

    git checkout main
git merge bugFix

    把 bugFix 分支融入 main。注意如果 Git 无法自动合并，这时候会报错

    Automatic merge failed; fix conflicts and then commit the result.

    此时需要你手动处理，处理完了提交一下

    git add --all
git commit

    返回历史版本

    首先用

    git log --oneline

    得到你要回退版本的 ID，随后通过

    git checkout ID

    所有文件就退回到提交的那个版本。如果你想回到最新状态请用

    git checkout main

    比较两次提交的差异

    通过

    git diff ID1 ID2

    你就知道两个版本的差异了。

    推送到云端

    由于我们的 git-learning 改动了好几次，接下去我们把他 push 到云端试试

    git push origin main

    这里的 origin 你可以理解为云端。发现 http2 传输出问题，我们输入

    git config --local http.version HTTP/1.1

    再

    git push origin main

    就成功了。注意，目前只有 main 分支被推送了，要推送 bugFix 分支，你要

    git checkout bugFix
git push origin bugFix

    从云端拉到本地存储库

    当本地存储库没懂，远程存储库变了，可以输入

    git fetch

    从远程存储库获取新的更改，但这些更新尚未出现在您的本地文件系统中。运行

    git merge

    才会出现在本地文件中。

    上面两步可以通过

    git pull

    撤销本地更改

    想象一下，你正在处理一个项目。你开始开发新功能，编写大量新代码，一段时间后，你意识到你采取的方法根本行不通。但到那时，您已经对10到15个不同的文件进行了更改。在这种情况下，你想回到以前的状态。这时候你就可以用

    git restore .

    这个命令可以帮助你将当前目录恢复到上次提交的状态。

    如果你希望清空暂存区

    git restore --staged .

    Git Stash

    当你 bugFix 分支工作到一半，但没改完 bug，所以你不希望 commit时。而你希望切换到 main 分支时会报错，因为 git 不允许你没保存就切换分支，这个时候就要用到 git stash 暂存来切换。

    撤销提交

    git revert 命令用于撤销在之前提交中所做的更改——但它不会删除旧的提交，而是创建一个新的提交来反转这些更改。

    git reset 可以带您回到特定的提交，并丢弃该点之后的所有提交，而无需创建任何新提交。 git revert 通过创建反向提交的新提交，从特定提交中删除更改。

    Git 基础概念速查表
    术语 含义
    repo 一个项目的 Git 管理单元。
    commit 一次版本快照（记录改动）及其说明；可用于对比与回退。
    branch 一条提交历史线的标签（如 main、dev）。
    checkout / switch 切换到指定分支。
    merge 将一个分支的改动合并到另一个分支。
    rebase 将一串提交“移到”新的基底上，重写历史以获得更线性的提交序列；常用于合并前同步主分支并整理提交。
    remote 远程仓库的地址/别名（如 origin）；常托管在 GitHub/GitLab 等平台。
    push / pull push 将本地提交推送到远程；pull 从远程拉取更新并整合到本地。

    Git 高级命令

    HEAD

    HEAD 就是你当前的位置，它通常指向当前分支。HEAD 还决定了你下一次 git commit 会接到哪条线上。

    当你提交一次

    git commit

    后，HEAD 是指向分支名 main 的。执行

    git checkout c1

    后，HEAD 就指向提交记录 c1 了。

    相对应用

    在实际应用时，并没有可视化提交树，你需要用 git log 来查查看提交记录的哈希值。哈希值很长，不过一般你只需要输入前几位就好了。通过哈希值指定提交记录很不方便，所以 Git 引入了相对引用。

    输入以下指定 mian 的 parent 节点。

    git checkout main^

    你也可以通过如下指令将 HEAD 从 C3 往上移动三次

    git checkout C3; git checkout HEAD^; git checkout HEAD^; git checkout HEAD^

    通过  <num> 也可以实现这一点

    git checkout C3; git checkout HEAD~3

    你也可以通过

    git branch -f main C6

    将分支强制移动到某个提交记录上

    撤销变更

    撤销变更可以用 reset 和 revert。

    假定现在 HEAD 在 main 分支上，提交记录是 c2，通过

    git reset HEAD~1

    可以将分支 main 退回到 c1，HEAD 依旧在 main 上。就好像 c2 没提交过一样。

    虽然在你的本地分支中使用 git reset 很方便，但是这种方法对大家一起使用的远程分支是无效的。为了撤销更改并分享给别人，我们需要使用 git revert。假定现在 HEAD 在 main 分支上，提交记录是 c2，通过

    git revert HEAD

    会多一个提交记录 c2’，提交的更改刚好撤销 c2。
