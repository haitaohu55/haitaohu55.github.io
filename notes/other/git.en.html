    What Is Git?

    Git is a tool that runs on a personal computer and records changes to files. It was developed by Linus Torvalds, the creator of Linux. Git is also described as a distributed version-control system: “distributed” means that every developer has a complete copy of the repository locally.

    Git stores snapshots of files as they change over time. Although these files are usually source code, Git is not limited to code: it can also track images, text files, and even videos. By recording every change, Git makes branch management and version rollback extremely fast.

    What Are GitHub and GitLab?

    GitHub and GitLab provide cloud hosting for Git repositories.

    Git Architecture

    Git has two main parts: local and remote. “Local” refers to your personal computer, while “remote” refers to a cloud service such as GitHub.

    On your computer, the project folder you are working in is called the working directory. This is where all changes occur. When you want to save a version, you move the changed files into the staging area, which acts as an intermediate zone. After confirming that everything is correct, you commit the staged files to the local repository. Git creates and manages system files inside the local repository to track changes, commits, and other repository data.

    Up to this point, everything has happened only on your computer; nothing has been sent to the cloud. A remote service is needed only when you want to share code, access it from another computer, or keep a secure backup.

    Git Quick Start

    Initialize a Local Repository

    First, open a terminal and enter

    git --version

    to confirm that Git is installed. Next, create a local folder on the desktop:

    cd ~/Desktop; mkdir git-one

    Create two text files in that folder:

    cd git-one; touch one.txt; touch two.txt

    Then create a subfolder:

    mkdir myfolder

    Enter myfolder and create another text file:

    cd myfolder; touch three.txt

    Open the current folder to confirm that all files were created correctly:

    open .

    Write “one” in one.txt, “two” in two.txt, and “three” in three.txt. To let Git track this folder, enter git-one and initialize Git:

    git init

    You can verify this with

    ls -a

    Create a Remote Repository on GitHub

    Go to

    https://github.com

    Click “New” on the left, enter the repository name and description, and click “Create” to make an empty repository. Next, choose “creating a new file,” create one.txt with the content “one,” and commit it. Repeat the same steps for two.txt. The two new text files will then appear in the repository.

    Clone a Remote Repository from GitHub

    Enter the following in the terminal:

    cd ../; git clone https://github.com/haitaohu55/git-learing

    The link is the URL of your repository. You can now find the cloned folder on the desktop. After entering the folder, you can also find its .git directory:

    cd git-learing; ls -a

    Inspect Changes Made in a Folder

    Modify and save one.txt in the git-learing folder, then enter

    git status

    You will see that one.txt is marked as modified. The git status command makes it easy to inspect changes in the working directory.

    Move Changes to the Staging Area

    The following command stages all changes in the working tree:

    git add --all

    You can then confirm the result with

    git status

    Use

    git reset

    to undo this staging operation.

    Related commands include

    git add -A
git add .
git add one.txt
git add myfolder/three.txt

    Commit from the Staging Area to the Local Repository

    After confirming that the staged content is correct, commit it to the local repository:

    git commit

    The terminal opens an editor for the commit message. After writing it, press Esc to leave editing mode and enter

    :wq

    to save and quit. Alternatively, provide the message directly:

    git commit -m "make some changes"

    Here, -m stands for “message.” Next, use

    git status

    to check whether the commit was completed. To undo this commit, use

    git reset HEAD~1

    This returns all changes to the working tree and removes this change from both the staging area and the local repository.

    Delete and Restore Files

    Delete one.txt directly from the folder, then enter

    git status

    to see that one.txt has been deleted. Next,

    git add --all

    stages the deletion. In fact, the two steps can be combined with

    git rm one.txt

    If you only want to unstage the deletion,

    git reset

    is sufficient. To unstage the deletion and restore the file, use

    git reset --hard

    Note that rm will not remove a modified but uncommitted file. To force its deletion, use

    git rm -f one.txt

    To delete a folder, use

    git rm -r myfolder

    View the Commit History

    Use

    git log

    to view the commit history together with the ID of each commit. For a more concise display, try

    git log --oneline

    Create a Branch

    Branches are one of Git’s most powerful features. Suppose you release a program at commit C1; one group now fixes bugs while another develops new features. You can create a branch with

    git branch bugFix

    The developers fixing bugs switch to bugFix and continue committing there:

    git checkout bugFix
git commit

    The developers working on new features continue committing on main. You can check the current branch with

    git status

    Merge Branches

    Eventually, the branches must be merged. Suppose you are fixing bugs on bugFix. After new features have been added, you do not want to keep fixing an outdated version, so you can run

    git merge main

    After finishing the bug fix, switch to main and merge bugFix:

    git checkout main
git merge bugFix

    This incorporates bugFix into main. If Git cannot merge automatically, it reports

    Automatic merge failed; fix conflicts and then commit the result.

    Resolve the conflict manually, then stage and commit the result:

    git add --all
git commit

    Return to an Earlier Version

    First, use

    git log --oneline

    to find the ID of the target version, then run

    git checkout ID

    All files now match that commit. To return to the latest state, use

    git checkout main

    Compare Two Commits

    Use

    git diff ID1 ID2

    to inspect the differences between two versions.

    Push to the Remote Repository

    After making several changes to git-learning, push it to the remote repository:

    git push origin main

    Here, origin is the name of the remote. If an HTTP/2 transport problem occurs, enter

    git config --local http.version HTTP/1.1

    and then run

    git push origin main

    again. At this point, only the main branch has been pushed. To push bugFix, use

    git checkout bugFix
git push origin bugFix

    Bring Remote Changes into the Local Repository

    When the local repository is unchanged but the remote repository has new commits, enter

    git fetch

    to fetch new changes from the remote. These updates do not yet appear in the local file system. Run

    git merge

    to merge them into the local files.

    The two steps can be combined with

    git pull

    Discard Local Changes

    Suppose you start developing a feature, write a large amount of code, and later realize that the approach does not work. By then, you may have changed ten to fifteen files and want to return to the previous state. You can use

    git restore .

    This command restores the current directory to the state of the last commit.

    To clear the staging area, use

    git restore --staged .

    Git Stash

    Suppose you are halfway through work on bugFix and do not want to commit an unfinished fix. Switching to main may fail because Git will not let you change branches while unsaved work would be overwritten. In this situation, git stash temporarily stores the changes so that you can switch branches.

    Undo a Commit

    The git revert command undoes changes introduced by an earlier commit. It does not delete the old commit; instead, it creates a new commit that reverses those changes.

    git reset can move the repository back to a specific commit and discard all later commits without creating a new one. By contrast, git revert removes the effect of a selected commit by creating a new inverse commit.

    Quick Reference for Basic Git Concepts
    Term Meaning
    repo The unit managed by Git for a project.
    commit A version snapshot that records changes and a message; it can be used for comparison and rollback.
    branch A label for a line of commit history, such as main or dev.
    checkout / switch Switch to a specified branch.
    merge Combine changes from one branch into another.
    rebase Move a sequence of commits onto a new base, rewriting history to obtain a more linear sequence; often used to synchronize with the main branch and organize commits before merging.
    remote The address or alias of a remote repository, such as origin; commonly hosted on platforms such as GitHub or GitLab.
    push / pull push sends local commits to the remote; pull fetches remote updates and integrates them locally.

    Advanced Git Commands

    HEAD

    HEAD represents your current position and usually points to the current branch. It also determines which line of history receives your next git commit.

    After you make a commit with

    git commit

    HEAD points to the branch named main. After executing

    git checkout c1

    HEAD points directly to commit c1.

    Relative References

    In practical work, there may be no visual commit tree, so you use git log to inspect commit hashes. Hashes are long, although entering their first few characters is usually sufficient. Because specifying commits by hash is inconvenient, Git provides relative references.

    The following command selects the parent of main:

    git checkout main^

    You can also move HEAD upward three times from C3 with

    git checkout C3; git checkout HEAD^; git checkout HEAD^; git checkout HEAD^

    The same result can be obtained with  <num>:

    git checkout C3; git checkout HEAD~3

    You can also use

    git branch -f main C6

    to force a branch to point to a particular commit.

    Undo Changes

    Changes can be undone with reset or revert.

    Suppose HEAD is on main at commit c2. Running

    git reset HEAD~1

    moves main back to c1 while HEAD remains on main, as though c2 had never been committed.

    Although git reset is convenient on a local branch, this approach is unsuitable for a remote branch shared by multiple people. To undo a change in a way that can be shared, use git revert. If HEAD is on main at commit c2, running

    git revert HEAD

    creates an additional commit c2’ whose changes exactly reverse those introduced by c2.
